OSR Updater 是一个中英文原生图形客户端，用于安装 OSRBOT 提供的固件
文件。客户端会验证所选文件、备份车辆设置、显示安装进度并明确报告最终
结果。客户端本身不内置固件。

## 主要特性

- 原生英文和简体中文界面
- 自动识别 ESP32-S3 应用程序镜像和完整烧写镜像
- App OTA 前可选保存可读的设置导出
- 每次完整烧写前保存与控制器绑定的完整车辆设置备份
- 不擦除设置分区的应用程序更新
- 支持标准布局和客户自定义布局的受保护完整烧写
- 仅在控制器身份和分区布局精确匹配时自动恢复设置
- 支持选择已保存的车辆设置备份并进行验证恢复
- 可直接打开备份和审计文件夹，并明确显示 SHA-256、进度和最终状态
- 使用严格文件权限保存审计记录和备份
- 面向 Jetson 系统的单一 Linux arm64 桌面软件包

## 安装

从 [GitHub Releases](https://github.com/osrbot/osr_updater/releases) 下载当前
`arm64.deb` 软件包及校验文件。验证校验值后，可以通过 Ubuntu 软件安装器
安装，或执行：

```bash
sudo apt install ./osr-updater_<version>_arm64.deb
```

安装后从应用程序菜单打开 **OSR Updater**。客户端不提供网页界面或面向
用户的命令行工作流。

## 标准更新

1. 停止占用控制器串口的 ROS 节点和其他软件。
2. 保持车辆静止并连接稳定电源。
3. 打开 OSR Updater 并检查控制器。
4. 选择为该车辆提供的应用程序固件文件。
5. 核对文件名、类型、大小和 SHA-256。
6. 选择“安装固件”并确认操作。
7. 在显示最终结果前保持连接和电源不变。

App OTA 不进入 ROM 恢复模式，也不会擦除或改写设置分区。当前运行固件提供
设置导出接口时，客户端还会保存一份可读诊断备份，并在重启后进行比较。界面会
提供“打开备份”按钮查看已保存的文件。

应用程序更新要求当前运行固件仍提供 OSR App OTA 命令。如果客户自定义固件
不再提供该接口，应改用完整烧写镜像。

## 完整烧写

完整烧写用于控制器恢复，或安装不使用 App OTA 的客户自定义合并镜像。一次引导操作会：

1. 验证所选 ESP32-S3 完整烧写镜像；
2. 进入 ROM 恢复模式，自动跟随 USB 串口重新枚举，并在任何擦除前保存当前完整设置分区；
3. 将备份与当前控制器绑定；
4. 要求独立的最终破坏性操作确认；
5. 擦除并安装所选镜像；
6. 只有设备身份及设置分区偏移和大小匹配时，才自动恢复已保存的设置并逐字节回读验证；
7. 目标布局不兼容时只保留备份，不向未知布局写入；
8. 报告已经验证的写入结果，并提示用户重启后重新检查控制器。

完整镜像写入后，请按提示按一次 RESET，使已安装固件启动。由于独立开发的镜像
可能不提供 OSR 协议，完整烧写完成后不会继续等待 OSR 协议响应。

完整镜像会按原样写入，包括其自身分区布局中包含的数据；原 Flash 数据会被
替换。接受最终确认前，应点击“打开备份”确认当前设置快照已经保存。

## 恢复出厂

先选择需要安装的完整烧写固件。客户端会按所选固件的 NVS 布局过滤备份，并显示
该控制器和设置布局对应的固定出厂基准。“恢复出厂”会在任何擦除前校验目标固件、
备份、控制器身份和分区布局；随后另存当前设置作为安全备份，安装所选固件，恢复
出厂基准并逐字节回读验证。

同一控制器、同一分区布局且内容完全一致的原始设置会复用同一份已验证数据文件。
具有已知来源固件的最早有效操作快照会固定为该控制器和设置布局的出厂基准；后续
安全记录仅作为审计证据保留，不会替换出厂基准。

完整操作和恢复说明请参阅[使用指南](docs/usage_zh.md)。

## 固件文件

OSR Updater 不内置固件。仅使用 OSRBOT 提供或明确批准、且与当前控制器
匹配的文件。客户端会验证文件结构和传输完整性，但无法认证独立修改固件
的功能行为。

## 故障处理

| 现象 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 无法打开控制器 | ROS 或其他工具占用了串口 | 停止相关进程，重新连接 USB 后再次检查。 |
| App 更新提示改用完整烧写 | 当前运行固件未提供 OSR App OTA | 选择完整烧写镜像，通过 BOOT/RESET 进入恢复模式后执行完整烧写。 |
| 无法导出可读设置 | 当前固件未提供 OSR 设置接口 | App OTA 仍会保留 NVS；更新后参数比较会标记为不可用。 |
| 传输开始前被拒绝 | 电源、车辆运动、镜像或设备预检查未通过 | 处理界面报告的条件后重新开始。 |
| 结果提示不得重试 | 应用传输或恢复状态存在不确定性 | 保留审计和备份路径，再联系 OSRBOT。 |
| 完整烧写后无法检查控制器 | 控制器尚未手动重启，或新固件未提供 OSR 接口 | 按一次 RESET，必要时选择运行态串口，然后重新检查设备。 |

## 开发

源码需要 Python 3.10 或更高版本、Tk 8.6、pySerial 和 esptool。

```bash
python3 -m unittest discover -s tests -v
```

正式软件包在 Linux arm64 环境构建：

```bash
./build.sh
```

构建只生成一个 Debian 软件包和对应 SHA-256 文件，不会加入任何固件载荷。
